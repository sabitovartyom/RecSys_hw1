# Домашнее задание 1: top-10 рекомендации

**ФИО:** укажите перед сдачей.

**Датасет:** [Amazon Review Data 2018 — Musical Instruments](https://cseweb.ucsd.edu/~jmcauley/datasets/amazon_v2/index.html), готовый 5-core (231 392 отзыва до очистки) и метаданные товаров. Рекомендуем ранее не оценённые товары; релевантность — будущая оценка 4–5.

## Docker

```bash
./build_image
./launch_container
docker exec -it recsys-hw1 bash
```

Откройте `experiments.ipynb` в контейнере и выполните все ячейки. Данные загружаются автоматически, результаты сохраняются в `results/`.

## Файлы

- `experiments.ipynb` — описание данных, EDA, формулы, подбор на validation, финальный test и выводы.
- `data.py` — загрузка двух архивов, очистка, индексация, временное разбиение, признаки товаров.
- `models/` — ItemKNN, iALS, EASE, FM, custom iALS; дополнительно Popularity baseline.
- `evaluation.py` — общий top-10 и NDCG@10 / Recall@10.
- `experiment.py` — последовательный перебор небольших сеток и финальное переобучение.
- `tests/test_small.py` — маленькие проверки формул и протокола на искусственных данных.
- `Dockerfile`, `build_image`, `launch_container` — окружение Docker.

Все модели реализованы через NumPy / SciPy / PyTorch, без готовых рекомендательных алгоритмов. У каждой одинаковый интерфейс: `fit(data, shape, item_features)` и `score(users)`.

## Протокол

После удаления некорректных строк сохраняется первое взаимодействие каждой пары пользователь–товар. Низкие оценки сохраняются. Границы train / validation / test общие по времени, приблизительно 80 / 10 / 10; одинаковые timestamps не разделяются. ID назначаются всему датасету только для индексации, но кандидаты и словари метаданных определяются по обучающей истории.

Подбор использует только validation, основная метрика — NDCG@10. После выбора настроек модели заново обучаются на train + validation и оцениваются на test. На каждом этапе все модели получают одинаковых пользователей и полный обучающий каталог кандидатов. Все известные пользователю товары, включая низкие оценки, исключаются. Пользователи и товары без обучающей истории не участвуют в основном сравнении. Пользователи без релевантных доступных товаров или с менее чем 10 оставшимися кандидатами также исключаются; notebook показывает количество исключений. Метрики усредняются по пользователям.

Для iALS confidence равен `1 + alpha` для любой наблюдаемой пары и `1` для ненаблюдаемой. Базовый таргет равен `1[rating >= 4]`. В custom iALS он умножается на `(rating - 3) / 2` для положительных оценок и на затухание с давностью. Confidence и критерий релевантности остаются теми же. FM использует бинарные метки оценок и случайные ненаблюдаемые обучающие пары как дополнительные отрицательные примеры. Отложенные взаимодействия при семплировании не просматриваются.

В таблице есть FM только с ID — дополнительный эксперимент для оценки пользы метаданных. Это не замена обязательной FM с метапризнаками.

## Ограничения и сдача

5-core уже отфильтрован авторами по всему периоду: это ретроспективный benchmark активных пользователей и товаров. Исторические версии метаданных отсутствуют; бренд и категория считаются постоянными. Текущие цены, рейтинги товаров, helpful votes и тексты будущих отзывов не используются. Рейтинг ниже 4 считается нерелевантным; это выбранная постановка, а не универсальная трактовка оценки 3. Отсутствие взаимодействия не доказывает отсутствие интереса, а timestamp отзыва не равен времени покупки.

Перед сдачей проверьте, что датасет не использовался на семинарах, заполните ФИО, выполните полный notebook, дополните выводы по результатам и создайте открытый GitHub-репозиторий. Данные и тяжёлые файлы исключены через `.gitignore`. Результаты полного обучения заранее не подставлены.
